# Data gotchas

What the tables do not say about themselves. Verified 2026-11-04 against go-nepse v0.2.5 and the local database; re-verify when go-nepse is bumped.

- **`fundamentals.eps` and `pe_ratio` are annualized.** The exchange scales the quarterly EPS to a full year. For hydropower, the Q1 (monsoon) figure overstates the year. Quarter-only EPS is derived, never stored.
- **`fundamentals.profit_amount` is year-to-date**, cumulative from Shrawan 1. Quarter-only profit = this row minus the previous quarter's row in the same fiscal year.
- **NEPSE sends profit and paid-up capital without a unit**, in whatever the company typed: rupees, thousands, lakh or crore, varying filing to filing (GBIME alone uses three). The worker rescales both to rupees before the upsert (`normalizeFundamentals`): paid-up against the company's median rupee-looking paid-up, profit against annualized EPS x shares x quarter/4. A profit between 10x and 30x off its EPS is stored NULL, since it is neither annualization noise nor a unit error. The feed also lists re-filings newest first and the worker keeps the first, so a corrected filing wins. Rows where EPS agrees with an odd profit stay as filed; the filing PDF at `source_url` is the only check.
- **Fiscal year strings.** `fiscal_year` holds the exchange's Gregorian span (`2026-2027`); the Nepali form (`2083/84`) is `FYNameNepali` in go-nepse. `quarter` holds `First Quarter` .. `Fourth Quarter`, empty for annual rows. Canonical display forms are defined in `GLOSSARY.md`.
- **Filing provenance exists in go-nepse** (report submitted date, filing path, document id) and is dropped until spec #20's provenance ticket lands.
- **Ownership is a snapshot** keyed by company; history only exists once `ownership_history` is written by the sync.
- **Dividend notices** carry headline and body as free text; book-close and AGM dates are not structured fields anywhere in go-nepse.
- **Which syncs run.** Monday to Friday: prices, market day, companies and fundamentals at 15:05 NPT; ownership and dividends at 10:00 (scheduled since #9). A fresh database has zero rows everywhere until `ntx backfill` runs; see `docs/deploy.md`.
- **Delisted companies keep their row.** The company sync upserts by exchange id and sets `status = 'D'` on every company the feed stopped returning; list, search, sector counts, sector distributions and the per-company sync loops (fundamentals, ownership, dividends, prices) filter on `status = 'A'`, while `GetCompany` by symbol still serves the old page and its history. A ticker rename keeps the id, so the row simply gets the new symbol.
- **Prices come from the live-market feed**, so `open_price` is null and holiday rows can repeat the last session (#11).
- **Mutual fund NAV and holdings** are a static JSON snapshot in the web app produced by `scripts/`, not database data. The `scripts/` project installs the OCR stack for those; the hydro scripts carry inline PEP 723 dependencies instead and run with `uv run --script`.
- **Bank metrics** (NPL, CAR, loan growth, distributable profit) do not exist in go-nepse. Whether they can be read from the filing PDFs: `docs/research/2026-11-09-lender-health-from-filings.md`. In v1 the owner types them into `bank_metrics` from the filing, one row per quarter with the published date and source URL required; bank gates read that table and show Needs data for a quarter that has a filing but no owner row.
- **Stored ratings carry a rule-set version** (`company_ratings.version`, `story.RatingVersion`). The startup fill recomputes every company when no row is at the current version, so a deploy that changes a check or the letter rule never serves old letters beside new ones. `holds`, `evaluated` and `total` feed the screener's coverage text.
- **Hydro plants are a CSV, not a sync.** `data/hydro_plants.csv` (141 plants, 110 companies) is drafted by `scripts/draft_hydro_plants.py` from the DoED operating and licence tables (snapshot of both pages in `scripts/data/doed/`, fetched 2026-11-05; the script reads it instead of DoED) and reviewed by hand; the worker upserts it on every start keyed on `(symbol, plant)`, and a row removed from the CSV keeps its table row. Coordinates are the centre of DoED's licence-area bounds, so a point can sit a few km from the intake. KBSH (0.998 MW) and SPL (0.99 MW) are under the 1 MW floor and have no row. The `cl` table is every generation licence, operating ones included; a plant is `under_construction` only when it is absent from the operating table.
- **Hydro readings come from two calls per plant per day.** Rain is Open-Meteo's forecast endpoint with `models=ecmwf_ifs025`; discharge is the flood endpoint (GloFAS v4, `seamless_v4`, modelled on a 5 km grid, not gauged). Either half of a `hydro_readings` row can be NULL until the other call lands. Today's rain is the model's figure for a day still running. Forecast days and rows older than ten years are never stored. The 06:00 NPT job runs every day of the week; `ntx backfill -weather` runs it now. A plant's first run fetches 92 days of rain and ten years of discharge, about 3,650 rows.
- **Plant state is never stored.** It is computed per request from the latest reading against the DHM 50 mm line and the plant's own nearest-rank 95th percentile of discharge over the last ten years; a plant without discharge rows cannot be "high discharge". The percentile pass sorts about half a million rows and takes a couple of seconds, so the API keeps the map in memory until the newest `fetched_at` moves: the first request after a weather run or a restart pays for it. The opening sentences of `/hydro` and the company Plants section are composed in Go (`internal/hydro/opening.go`), as ADR 0001 requires.
- **Map data is a build artefact.** `apps/web/src/lib/data/hydro_map.json` comes from `scripts/build_hydro_map.py` (geoBoundaries ADM0, CC BY 4.0; HydroRIVERS v1.0 under the HydroSHEDS licence, which allows derived works with attribution; both confirmed 2026-11-05 from the geoBoundaries site and the HydroSHEDS technical documentation v1.4, appendix A). The ICIMOD point layer was not used, so its reuse terms were not needed. Rerun the script after a CSV edit that adds a plant on a river below Strahler order 4.
